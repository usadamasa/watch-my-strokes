# 要件定義: watch-my-strokes

Issue [#1「原案」](https://github.com/usadamasa/watch-my-strokes/issues/1) の深掘り。

## 1. 実現したいこと(ゴール)

**「横で見てくれている先生」のような、リアルタイム描画・手書きAIコーチのプロトタイプ。**

ユーザーが紙に絵や文字を描いている様子をWebカメラで撮影し、AIが定期的に手元の状態を観察して、
**短く・具体的で・今役に立つ**アドバイスを音声で返す。

### ゴールでないもの(明示的スコープ外)

- 30fpsの生映像をLLMに送ること(コスト・レイテンシ的に不可。低頻度スナップショット方式を採る)
- 完成作品の採点・講評(「画像の採点者」ではなく「傍で見る先生」)
- ペン先トラッキング・筆順・筆速の評価(将来拡張。MVPでは扱わない)
- 筆圧の推定(Webカメラでは原理的に困難。タブレット入力は将来検討)
- ユーザー管理・永続化・複数セッション履歴(MVPはブラウザ1タブ=1セッション)

## 2. ユーザーストーリー

| # | ストーリー | 受け入れ条件 |
|---|---|---|
| U1 | 描き手として、カメラを紙の上にセットして描き始めるだけでコーチングを受けたい | カメラ許可→紙領域選択→開始、の3ステップ以内でセッションが始まる |
| U2 | 描いている最中に、手を止めずに耳でアドバイスを受け取りたい | フィードバックはTTSで読み上げられ、画面にも表示される |
| U3 | うるさいコーチは嫌だ。意味のある指摘だけ欲しい | クールダウン(既定5秒以上)+変化検知+モデル側の「言うことがなければ黙る」の三段抑制 |
| U4 | 指摘は一度に一つだけにしてほしい | 1回のフィードバックは1つの実行可能な提案のみ(文字数上限あり) |
| U5 | 前の状態からの変化を見てほしい(毎回全体を採点し直さないでほしい) | モデルには直近数フレーム+過去の指摘履歴をコンテキストとして渡す |
| U6 | 開発者として、カメラ・APIキーがない環境でも動作検証したい | シミュレーション映像ソース+モックコーチで全ループがE2Eで動く |

## 3. 機能要件

### F1. 映像取得
- `navigator.mediaDevices.getUserMedia()` でWebカメラ映像を取得しプレビュー表示する。
- カメラが使えない/使わない場合のために**シミュレーションソース**(Canvas上で描画が徐々に進む合成映像)を選択できる。
  - シナリオ: ドローイング(線画を徐々に描く)/手書き(文字列を1画ずつ書く)。意図的な崩れ(傾き・プロポーション)を含み、コーチが指摘できる素材にする。

### F2. 紙領域のクロップ
- プレビュー上でドラッグして矩形の紙領域を指定できる。未指定なら全体を使う。
- 以降のフレームキャプチャはクロップ領域のみを切り出して送る。

### F3. フレームキャプチャ
- 設定間隔(既定1.5秒、0.5〜5秒で可変)でクロップ済みフレームをJPEG(長辺~768px、品質~0.7)にエンコードする。

### F4. 変化検知(クライアント側・送信前の足切り)
- 直前送信フレームとの差分をダウンスケール済みグレースケールの画素差で算出(`changeScore` 0..1)。
- 閾値未満なら**送信自体をスキップ**(APIコストと無駄な発話を抑制)。

### F5. クールダウン
- 最後の発話から最小クールダウン(既定8秒)以内は、変化があっても問い合わせない。
- 状態機械: `idle → capture → (変化あり?) → (クールダウン明け?) → ask → (介入あり?) → speak → cooldown`

### F6. コーチング(バックエンド)
- セッション単位で会話コンテキストを保持(直近Nフレームの画像+これまでの指摘履歴)。
- システムプロンプトはIssue記載の方針に従う:
  - 「毎フレームにコメントしない」「前の状態と比較」「優先度: ①全体の形とプロポーション ②位置と角度 ③線の質 ④細部」「提案は一度に1つ」「言うことがなければ黙る」
- 応答はJSON `{ intervene: boolean, message?: string, focus?: string }`。`intervene=false` なら無言。
- プロバイダは差し替え可能:
  - `AnthropicCoach`: Claude vision モデル(既定 `claude-opus-5`、`COACH_MODEL` で変更可)
  - `MockCoach`: APIキー不要。フレームのメタ情報(changeScore、インク被覆率、経過時間)から決定論的にコーチ挙動を模倣。CI・シミュレーション用。

### F7. 音声出力
- 介入メッセージを Web Speech API (`speechSynthesis`) で読み上げる。読み上げ中は次の発話をキューしない(最新を優先し古いものは破棄)。
- 音声が使えない環境(ヘッドレス等)でも画面表示とログには残る。

### F8. セッションログ
- 画面右にタイムライン(キャプチャ/スキップ/問い合わせ/発話)を表示。JSONとしてエクスポート可能。

## 4. 非機能要件

| 項目 | 要件 |
|---|---|
| レイテンシ | フレーム送信→フィードバック表示まで p50 < 4秒(モック時 < 200ms) |
| コスト | 送信は最大 ~0.7fps。変化なしフレームはAPI到達前に足切り。モデルへ渡す画像は直近N枚(既定3)に制限 |
| プライバシー | 映像はブラウザ内で処理し、送信されるのはクロップ済み低解像度スナップショットのみ |
| 秘匿情報 | APIキーはサーバー側環境変数のみ。フロントには出さない |
| テスト容易性 | 変化検知・クールダウン・コーチエンジンは純関数/注入可能な依存で単体テスト可能にする |
| 検証容易性 | カメラ・APIキー・人間の操作なしで、ヘッドレスブラウザによるE2Eシミュレーションが1コマンドで走る |

## 5. アーキテクチャ

```
[Browser]
  映像ソース (Webカメラ | シミュレーション)
    → クロップ → 1〜2秒毎にJPEGスナップショット
    → 変化検知 (足切り) → クールダウン判定
    → POST /api/sessions/:id/frames  (base64 JPEG + メタ情報)
[Server (Node/TS)]
  CoachEngine (セッション文脈: 直近Nフレーム + 指摘履歴)
    → CoachProvider (Anthropic | Mock)
    → { intervene, message }
[Browser]
  → 表示 + speechSynthesis で読み上げ → クールダウン開始
```

- 送信頻度が最大 ~0.7fps と低いため、MVPの転送は WebSocket ではなく **HTTP POST** で十分(シンプルさ優先)。リアルタイム音声モデル等に移行する際にWebSocket/Realtime APIを導入する。

## 6. 将来拡張(Issue #1 より、本MVP対象外)

- OpenCV.js による紙検出・射影補正・明度正規化・ペン先トラッキング
- 筆順・筆速のローカルCV評価、タブレット/スタイラス入力
- 練習課題の自動生成、難易度調整、セッションサマリー、弱点検出、進捗保存
